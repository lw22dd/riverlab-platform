# 都江堰三维营造纪事：移植与建模说明

本文记录「开山导江记」从单文件离线版（`standalone/`）移植进 SPA 的完整过程，供论文「系统实现」与「三维建模」两章引用。数字均可由单测或构建产物复现。

## 1. 一套引擎，两个路由

| 路由 | 形态 |
| --- | --- |
| `/scenario/dujiangyan-build` | 决策推演：同一引擎当 3D 舞台，节点动作驱动时间窗与分支，六次决策写回同一批参数 |
| `/chronicle/dujiangyan` | 自由观看：八幕 64 秒、跳幕、拖时间轴、换机位、六项工法实验、建模提单 |

唯一有界面入口的是运行页——主题页 `/experiments/dujiangyan` 的「建造过程仿真」场景卡；纪事页保留为直连地址（答辩演示自由观看时手动打开），主题页不再挂「三维营造纪事」入口卡。

## 3. 反演规格（`spec.ts`）

平面坐标记 `[X 东, Z 北]`，入世界时 `p2w(X, Z, y) = (X, y, -Z)`。尺度为概化单位：**1 长度单位 ≈ 20 m**。

- `PROFILE_TABLE`：14 条断面，每条 `[Z, 西岸 xW, 崖脚 xE, 脊线 xR, 东界 xE_east, 脊高]`。玉垒山主峰在 `Z=-7.8`、脊高 `8.6`；宝瓶口颈在 `Z=-16.97`、崖脚 `X=16.15`。
- `GAP`：宝瓶口走廊，`from [13.4,-15.6]` → `to [21.4,-19.8]`，底宽 `0.85`；派生 `GAP_LEN` 与单位向量，供地形开挖与标签投影共用。
- `DIKE_AXIS`：金刚堤脊线六点，起于鱼嘴迎水尖 `[-12.78, 26.25]`，止于飞沙堰北端 `[2.14, -17.79]`；`WEIR_AXIS` 从同一点向东 `[9.60, -17.05]` 收尾。`WEIR_LEN` 由折线积分得 **7.4629**，是溢流公式的堰长。
- `SANDBARS`：三处天然江心洲（`bar1` 长 11.0 顶高 0.22、`bar2` 长 10.5 顶高 0.19、`bar3` 长 6.4 顶高 0.14），前两处 `forDike`，竹笼堤正是「依洲筑堤」。
- `CANALS`：四级自流渠网八条，干渠宽 1.7、两支渠 1.1/1.15、六条支渠 0.65，各带出场时间窗。
- `PHASES`：八幕 `before / fire_quench / chisel / cages / split / weir / maint / harvest`，秒数 `8/8/8/9/8/8/7/8`，合计 **64 秒**；`PHASE_STARTS = [0,8,16,24,33,41,49,56]`。
- `LABEL_DEFS`：24 条屏幕标签，分四级：一级地名（玉垒山、宝瓶口、鱼嘴）、二级工法（竹笼鱼嘴、飞沙堰）、三级水情注记（「天然浅洲（洪期没顶）」）、四级史注（「明清 · 卵石鱼嘴 / 定名飞沙堰」）。

## 4. 地形与水体

`sampleTerrain(X, Z, { carve })` 是全域唯一的解析式高程，五段分区求解：

1. 河床 `X ∈ [xW, xE]`：`y = lerp(-0.32, -0.70, smoothstep(u, 0.25, 0.78))`，宝瓶口内侧挖出伏龙潭至 `-0.72`。
2. 西岸漫滩与丘陵：`0.22 + 0.36·s(w) + 0.14·s(w) + 3.2·s(w)·…`，`dw<14` 记 `westFlood`，更远为 `westHill`。
3. 玉垒山脊：西坡 `t^0.50`（崖段更陡）、东坡 `t^1.15`，再按脊高叠噪声，`t<0.72` 归 `cliff`。
4. 宝瓶口开挖：走廊内按 `wallY = -0.68 + max(0, d - halfW)·3.45` 挖倒梯形，`halfW = 0.85 + 0.75·(两端扇形余量)`，两端各有 `alongFade` 过渡，避免出现直壁断口。
5. 东侧成都平原：`0.34 + n1·0.045 + n2·0.025 + smoothstep(Z,-16,42)·0.55`，再沿 `CANALS` 下切浅槽（干渠 0.28、支渠 0.18）。

三条路径共用这一函数：地形网格顶点、水体 shader 的河床线、镜头贴地判定。因此「改一处等于改三处」，不会出现水体浮在地表之上的穿帮。

水体是**单张连续网格 + shader**：`uFlood`（水位）、`uGapOpen`（宝瓶口开启度）、`uWeirHigh`（堰顶高程档位归一化 0/0.5/1）、`uSpill`（溢流强度）三个关键 uniform 都由每帧求解结果写入，所以分支实验改的是同一支公式，不是另画一套贴图。

## 5. 水理解析式（`hydraulics.ts`）

六项分流按断面输水能力分配：

```
B_in  = 4.20·(1 − 0.10·p)     B_out = 5.20·(1 + 0.06·p)     p = 鱼嘴偏置(−1/0/+1)
h_in  = 0.70 + 0.55·q         h_out = 0.42 + 1.05·q           q = 来水（0 枯 … 1 洪）
K_in  = B_in·h_in^(5/3)       K_out = B_out·h_out^(5/3)
R_in  = K_in / (K_in + K_out)
z_up  = −0.30 + 1.55·q        （上游水位）
Q_spill = 1.70 · WEIR_LEN · max(0, z_up − z_crest)^1.5        （宽顶堰）
η_sand  = 0.78 · Q_spill/(Q_spill + 8.0) · e^{−2.2·max(0, z_crest − 0.55)}
v_flow  = 1.20 + 3.60·q       K = clamp(v_c / v_flow, 0, 2.5)  （v_c：竹笼 4.8 / 砌石 2.6 / 夯土 1.3）
Q_rel   = (h_eff / 0.70)^(5/3)（h_eff：深淘 0.70 / 浅淘 0.44）
```

堰顶三档 `z_crest`：低堰 0.62、中堰 0.88、高堰 1.24。单测实测值（可直接进论文）：

| 量 | 枯水 q=0.18 | 洪水 q=1.0 |
| --- | --- | --- |
| 内江分水比 `R_in` | **0.5596** | **0.3790** |
| 低堰溢流量 `Q_spill` | 0 | **6.3734** |
| 高堰溢流量 `Q_spill` | 0 | ≈0（`z_up=1.25` 仅高过堰顶 0.01） |
| 竹笼抗冲比 `K` | 2.50（封顶） | **1.00**（恰在起动线） |
| 夯土抗冲比 `K` | **0.703** | 0.271 |

排沙效率在低堰 `q=1` 时为 **0.2965**；浅淘的过流能力只有深淘的 **0.4613**（`(0.44/0.70)^{5/3}`）。

这组数字正是「深淘滩、低作堰」六字诀的定量解释：

- **低作堰**：堰顶低 → 洪水期 `Q_spill` 大 → 排沙效率高、上游不壅水；代价是枯水期蓄水少。
- **深淘滩**：深淘把过流能力拉满到 100%，浅淘只剩 46%，来水稍大就会壅高上游。
- **竹笼卵石**：抗冲比在洪水期刚好 1.00，是「既省料又不至于一冲就散」的临界选择；夯土在枯水期就已经低于起动流速。

## 6. 四张答辩面板（`experiments.ts`）

| 面板 | 曲线 | 读法 |
| --- | --- | --- |
| 内外江分水比 | `R_in(q)` | 枯水内江占优（四六分水），洪水外江反超 |
| 飞沙堰溢流量 | 低堰实线 vs 高堰虚线 | 同一洪水下高堰几乎不溢流 → 泄洪排沙余量被吃掉 |
| 堤身抗冲裕度 | 三材料 `K(q)` + `K=1` 基线 | 低于基线即起动冲毁 |
| 岁修淘滩过流 | 深淘 100% vs 浅淘 46% | 与当前选择无关，只换高亮，用来对比而非读数 |

四张图与三维水体共用同一支解析式（`solveHydraulics` 的返回值），不存在「图上是 A、水里是 B」。

| `legacy` | `[24, 18, 40]` | `[10, 2, 12]` | 从平原回望山体与全套工程 |

两条取景经验记在这里，改机位时会反复用到：**① 机位必须在节点真实时刻验收**——同一机位在末幕好看，在凿宝瓶口的第 20 秒可能被整块岩体挡住；**② 离堆与玉垒山南坡会挡住从南/西南看向宝瓶口的视线**，从南侧取景必须抬高并把 `look` 往西北挪。决策节点 `focus` 为 `null`，保持上一机位不动。

`ambience` 只有 `critical` 强制洪水位，其余交给脚本按幕推进。

## 8. 与运行页的接缝

`buildChronicleStage(host, options)` 实现 `ScenarioStageHandle`：

- 纪事引擎不持有渲染循环，适配器自己 `requestAnimationFrame` 调 `scene.tick(dt)`，并渲染 `CSS2DRenderer` 热点层。
- 播放窗口到点即停（`playUntil`），不会从第 8 幕回落第 1 幕打断决策；`reducedMotion` 开启时直接落到窗口终点。
- 热点沿用 `stage.ts` 已有的 `.world-hotspot` 结构与样式，三个 id 与场景 JSON 的 `inspected` 规则对齐：`d_spot_ridge`（玉垒山嘴）、`d_spot_bend`（内江弯道）、`d_spot_plain`（平原引水口）。
- 屏幕标签样式抽到全局 `styles/chronicle-labels.css`，纪事页与运行页共用 `.scene-labels / .scene-label / .tier-1..4`。

- 内置补偿：`fitCamera` 在宽高比 < 1 时按 `1.15/aspect` 拉远机位（上限 1.58）并把视场从 38° 放宽到 48°，`resize` 时对固定机位重算，所以 9:16 竖屏不会只截到山谷中间一条。

## 10. 已知边界

- `scene.ts` 为逐段直转，`@ts-nocheck`；改动它时以浏览器实测为准。
- 概化单位（1 单位 ≈ 20 m）不是测绘尺度，断面与秒数服务于「能不能讲清取舍」，不追求水文原型精度。
- 旧的 v1 沙盘 `three/scenes/dujiangyan.ts` 已从分发点摘除（不再被打包），保留在仓库中作为早期实现对照；其中的 `dujiangyan-hydraulics.ts` 与纪事公式不是同一套，引用数据请以 `three/chronicle/hydraulics.ts` 为准。
